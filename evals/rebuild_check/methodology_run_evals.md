# Running an eval item

One row per case. An eval item carries the case's source files, the shape an answer should
take, and what the artifact expects. Nothing here reads a web page: the item was generated by
a separate run and is a fixed thing this can be re-run against.

`resolve_sources` turns the case's checkout-relative source paths into paths on this machine,
and stops a case whose file is missing.

`blind_build` renders into its prompt only the columns it reads — the source paths and the
answer's shape — and the loader refuses a prompt that names any other column. So the expected
answers flow past the build unread, and `blind_build` hands back a run, not figures. Its
pipeline's last stage must be `answer` and write one row in the shape asked for. A build that
cannot get there returns no run and says what stopped it, which is a result rather than a
failure to report.

`verify_citation` asks the workspace whether the cited run finished; a run that errored has no
answer to read, whatever files it left behind. `read_answer` then reads the figures out of
that run's `answer` stage.

`compare` grades each figure, type first: the schema declares a type, so a value of the wrong
type is graded `wrong_type` rather than compared — an integer field answered with a date is a
failure of the build, not a disagreement about a number. A value of the right type is then
checked against what the artifact states.

`diagnose` rules on each disagreement the comparison found — our defect, their defect, genuine
ambiguity, or consistent with hedged wording the rebuild's exact value satisfies. `verdict`
passes the case unless a figure is ruled our defect, or the citation or the comparison did not
hold.
