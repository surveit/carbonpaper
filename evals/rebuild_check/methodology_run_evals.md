# Running an eval item

One row per item. An item carries input files, the shape an answer should take, and what the
artifact expects. Nothing here reads a web page: the item was generated by a separate run and
is a fixed thing this can be re-run against.

`build_brief` drops the expected answers. Everything below works from a frame that does not
carry them, so the build has no column to read them out of — the blindness is the schema of
that frame, not a rule in a prompt.

`blind_build` hands back a run, not figures. Its pipeline's last stage must be `answer` and
write one row in the shape asked for; `read_answer` opens that stage's output. A build that
cannot get there returns no run and says what stopped it, which is a result rather than a
failure to report.

`verify_citation` asks the workspace whether the cited run finished. A run that errored has no
answer to read, whatever files it left behind.

Grading is per quantity. The schema declares a type, so a value of the wrong type is graded
`wrong_type` rather than compared — an integer field answered with a date is a failure of the
build, not a disagreement about a number.
