{# The certification badge that sits directly under an authored-code stage's plain-language summary: has that summary been checked against the code, and on how many cases. Context: certification (app.web.stage_test_views.StageCertification). The wording is the point of this partial. A reviewer who cannot read the code is trusting the sentence above it, so the badge has to say exactly what earns that trust and exactly what it does not cover — the tests are authored from the methodology, never by running the code, so passing means the description and the code AGREE ON THESE CASES. It is not a correctness proof, and a green badge must not read like one. `n/a` is grey and says "nothing to check", never a green tick: no example ran and nothing was verified, so a tick would claim a check that never happened. Only the config-only blocks call it in that state — a stage whose behaviour is a prompt has prose a reviewer cannot check either, which is a different thing to say. #} {% macro stage_certification(certification) %} {% if certification %}
