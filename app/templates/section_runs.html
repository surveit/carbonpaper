The Filter box above the table is a separate, client-side narrowing over what is already on the page (runs-filter.js), matching name, filename and version message. Fixed layout with declared column widths: under `auto`, the widest cell in a column sets that column's width and takes it from its neighbours, and a version message runs to hundreds of characters. The view picker splits runs into three mutually exclusive buckets — production (the default), test, and archived — with restore in place of archive on the archived view. Archiving hides a run from the other two buckets and nothing else: the run page, its outputs, its cost and the overview counts are untouched, which is why this needs no confirmation and no warning. Configuring a run is a different task from reading the history, and has its own fields — it lives on its own page (section_run_new.html), which the "▶ New run" action and the empty state link to.
