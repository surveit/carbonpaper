Two pages index issues this way, and they are read by the same person minutes apart: the run page (what this run's records say went wrong) and the Workflow page (what is wrong with the workflow as written). One table, so reading the second costs nothing once the first has been read. A row is: the severity WORD · the stage · a narrow qualifier · the message. The qualifier is whatever that page has that is narrower than a sentence — a column name on a run, the warning kind on the workflow — and `tags` trail the message as small codes (on a run, the reports that raised the same line). A stage link carries [data-stage-link], the app-wide "open this stage" hook, and `tab` names which of the stage panel's tabs to open where the page has tabs. The panel is titled by its COUNTS and nothing else — "18 warnings, 3 errors" — so the two pages cannot drift into describing the same list differently. A count of zero is not written: "0 errors" reads as a result, and the result here is the other number. It opens CLOSED on both pages. The counts are the summary, so a reader still meets the fact that something is wrong without the table pushing the page's own subject down; opening it is one click, and neither page can differ on the default. #} {% macro issue_panel(errors, warnings) %}
